Arquitectura Academia MKT + IA

Plataforma de cursos de marketing digital e IA donde el administrador decide quién enseña. Next.js renderiza y ejecuta todo en el servidor; Supabase guarda los datos y hace cumplir cada permiso dentro de Postgres.

  • Next.js 15.5 · App Router
  • React 19
  • TypeScript estricto
  • Tailwind 4
  • Zod 4
  • Supabase Auth
  • Postgres + RLS
  • pgTAP · Vitest
  • Node 24

Contenedores

Vista del sistema

Hay tres piezas: el navegador, el servidor de Next.js y el proyecto de Supabase. El navegador nunca habla directamente con Supabase: todas las lecturas y escrituras pasan por Server Components y Server Actions, que consultan con la sesión del usuario. Por eso RLS siempre sabe quién pregunta.

Secuencia

Una petición por dentro: "Inscribirme"

El botón de inscripción es el mejor ejemplo de cómo se reparte el trabajo. El Server Action casi no valida reglas de negocio: inserta y deja que la base decida. Así la regla vive en un solo sitio y nadie puede saltársela.

Esquema public

Modelo de datos

Siete tablas propias más auth.users de Supabase. La separación más importante es lessons frente a lesson_contents: RLS filtra filas, no columnas, así que el título (temario público) y el contenido (solo inscritos) viven en tablas distintas con políticas distintas.

Autorización

Matriz de permisos

Quién puede hacer qué, y en qué parte de la base se hace cumplir. Un instructor es también estudiante: puede inscribirse y reseñar cursos ajenos. El admin no tiene acceso especial al contenido: su poder es decidir quién enseña.

AcciónVisitanteEstudianteInstructorAdminDónde se cumple
Ver catálogo, ficha y temario de cursos publicados sísísísí RLS courses_select_visible · lessons
Leer el contenido de una lección nosi está inscritodueño o inscritosi está inscrito RLS lesson_contents: owns_course o is_enrolled
Inscribirse en un curso nosísolo ajenossí RLS with check + can_enroll · UNIQUE
Escribir, editar y borrar su reseña nosi está inscritoinscrito, no dueñosi está inscrito RLS reviews · GRANT update (rating, comment)
Crear y editar cursos y lecciones nonosolo los propiosno RLS is_instructor() y dueño
Publicar un curso nonopropio, con 1+ lecciónno trigger courses_guard_publication (CP001)
Borrar un curso nonopropio, sin inscritosno FK enrollments ON DELETE RESTRICT
Otorgar o quitar el rol instructor nononosí RPC set_instructor_role verifica is_admin()
Cambiar su propio rol nononono GRANT update solo (display_name, bio)

Cuando un admin degrada a un instructor, sus cursos desaparecen del catálogo en la siguiente navegación: la política de cursos exige is_active_instructor y el middleware lee el rol de la base en cada request, no del token.

Patrones que se repiten

  • Formularios: Server Action + useActionState + Zod en el servidor. El hook useFormAction conserva lo escrito cuando la validación falla (React 19 reinicia el formulario).
  • Errores de base de datos: lib/db-errors.ts traduce códigos (42501, 23505, y los propios CP001 a CP003) a mensajes legibles.
  • Contenido de lecciones: react-markdown sin HTML crudo, para evitar XSS.
  • Login y logout: navegación completa con window.location.assign para que la siguiente página llegue con las cookies correctas.

design.md

Decisiones clave

D1

Sin backend propio

Server Components y Server Actions. Supabase ya es la API y la autorización vive en RLS; un Express aparte sería una capa más sin valor.

D2

Un rol por usuario en profiles

No en el JWT: un cambio de rol debe aplicar en la siguiente navegación, no cuando se refresque el token.

D3

El rol solo cambia por RPC

Dos defensas independientes: GRANT por columna y una función que verifica que quien llama sea admin.

D5

Lecciones y contenido separados

RLS protege filas, no columnas. Dos tablas permiten temario público y contenido privado.

D7

Reglas en la base

UNIQUE, CHECK, FK y triggers. Si una regla vive solo en la app, cualquiera se la salta llamando a la API.

D8

Promedio con vista

catalog_courses calcula promedio y conteos al consultar: siempre consistente, sin sincronizar columnas.

D12

pgTAP sin Docker

Runner propio contra la base remota. Las pruebas son compatibles con supabase test db si algún día hay Docker.

Fuera de esta versión: pagos, video propio, progreso por lección, certificados y búsqueda por nombre de categoría. Todo el detalle está en openspec/changes/archive/2026-10-26-create-course-platform/design.md.
